# Taiwan-LLM-Sanitizer｜下一階段簡明路線圖

> 2026-10-25 的**產品與研究規劃**，不代表以下功能已經發布或有既定完成期限。已完成能力及限制請看 [功能狀態](FEATURES.md)。

## 產品戰略

**我們是跨模型的「臺灣繁中在地化、安全保真與可驗證控制層」，不是訓練大型語言模型的計畫。** 重點是讓使用者自主選詞、保護技術結構並查核結果，而不是追逐參數量、單一翻譯排行榜或強制所有詞彙改成一種說法。

公開核心應能在 **Chrome／Tampermonkey／CLI／開發者與 AI 工作流** 重用同一套安全、可回復及使用者自主詞彙契約。Provider 可替換，但傳送資料、保存成本、模型授權與能力必須透明且經使用者同意。

## 永久不退讓的限制

1. **允許保留原詞，不設地區用語禁令**；有歧義就提示上下文，不強制轉換。
2. **安全與隱私先於翻譯字數**：預設不蒐集頁面文字；不將 R3 883 候選、R10 40 例句無審核直接升級執行。
3. **不把 CI 成功解讀成模型翻譯品質**。R12 是品質分析工具，尚無經獨立評審確認的真實自然度成績。
4. **歷史版本不混淆**：R11 v0.5.0 是最新通用瀏覽器預覽；R5 v0.4.0 是保留的舊版；R12 是研究工具。
5. **MIT／Open-Core／第三方授權分離**。任何第三方模型權重、詞庫或其他受限素材，未完成授權核對不得當成 MIT 資產納入封包。
6. **每次版本更新留下兩份完整封存**：公開程式原始碼及安裝檔；私人完整決策、歷程、測試、踩雷與接續 ZIP。私人包不可進公開 Repo。

## 為什麼不先做完整 OCR／PDF？

這些能力有市場價值，但需要獨立的影像辨識、版面還原與版權處理技術。當前優先處理真實閱讀體驗、技術保真與品質證據，以免同時增加多個無法驗收的系統。

**公開產品介紹採中立寫法**：描述本專案功能、限制與可重現證據，不以具名競品對照、排行榜、指控或連結作為首頁賣點；詳細市場分析及研究來源留在私人專案大腦。


## R13 雙語閱讀安全側車（2026-10-25）

已建立**獨立 opt-in Preview 0.6.0**，只讀取主動選取的網頁文字，顯示封閉側車與原文/候選譯文，不修改網站原文；Chrome 本機翻譯在可用時才由使用者點選啟動。UI 操作 click 預設建議「點選」，並保留非 UI 反例。這不是正式整頁翻譯替代品。下一步：真實跨網站/Chrome 裝置能力測試、可反證品質研究與模型中立 Provider 設計。

## R14 離線能力／同意決策 Shadow（2026-10-25）

已建立獨立的純離線 Provider capability/consent 判定模組、CLI 和 HTML 示範頁，不涉及真正雲端翻譯或裝置實機模型偵測。R5/R11/R13 舊版不變。下一步是取得真實模型能力與使用者測試證據，再判斷是否將經驗證的 API 安全整合至現有閱讀流程；不得把未授權遠端傳輸當作已交付功能。

## R15 結構保真 Shadow 原型（2026-10-25）

本輪先完成獨立 Markdown／JSON／Prompt 受保護片段分析、不可變來源 SHA256 與人工審核差異預覽，僅提供離線 HTML／Node CLI。這是保守詞法掃描，非完整 AST，也不會對真實資料進行自動翻譯、套用或上傳。未來若要擴充到跨檔案格式，必須另做合法測試、使用者驗收與結構反證；先維護第三方著作權、商標、資料來源及隱私保護。
