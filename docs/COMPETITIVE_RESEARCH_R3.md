# R3 市場分析｜如何創造與通用翻譯器不同的價值（2026-10-24）

## 外部市場事實（與本專案計畫分開）

- OpenCC 提供高品質、確定性的繁簡／臺灣地域詞轉換，有 `s2twp` 等路由，Apache-2.0：https://github.com/BYVoid/OpenCC 。我們不能宣稱首創簡繁/臺灣詞轉換。
- Immersive Translate 已有雙語網頁、PDF、影片字幕、滑鼠懸停、輸入框、多引擎及 OCR：https://immersivetranslate.com/en/docs/ 。只加「雙語翻譯」不構成獨家。
- Google Chrome Translator API 桌面版提供 on-device 語言翻譯；實際支援有瀏覽器及語言組合條件：https://developer.chrome.com/docs/ai/translator-api 。我們的獨特性不能只建立在「使用 Chrome 本機模型」，因為這是公開平台 API。
- OpenAI Codex for OSS 官方重視活躍核心維護、真實使用、生態系重要性與維護工作，沒有公告任何「做某種詞庫就較容易入選」或「達多少 Star 必成功」的標準：https://openai.com/form/codex-for-oss/ 。

## 建議的市場定位

**Taiwan-First, User-Controlled, Private-by-Default, Developer-Safe Localization Infrastructure**

不是民族語言警察，也不是不能用中國或英文原文。目標是給每個使用者自主選擇臺灣化程度，並讓技術內容不被翻壞。

## 吸引大眾的使用流程

- 在 GitHub 看英文 README，點一次 → 臺灣繁中與原文對照，程式碼、命令和 Prompt 佔位符不改。
- 在外國/中國網站，使用者自己選「原文／繁中偏好／雙語」，系統按上下文建議「Menu → 主選單」或「Menu → 菜單」，非強制。
- 直接將 Markdown/JSONL 交給本地 CLI，得到可比較、可還原、可驗證的輸出；不必交出資料給第三方。
- 提案者只提供自願詞彙，社群在 GitHub 檢驗正例/反例，不必允許軟體收集瀏覽內容。

## 市場與 OSS 證據怎麼做

透明公布 benchmark corpus、通過率、錯誤率、修復記錄、GitHub Issues/PR、真實 Release 和維護日誌。不透過暗中遙測蒐集頁面，不刷 Star、不假裝已有採用率。社群宣傳重點是「能現場操作的實用問題與修復前後」，而不是『三天保證達 100 星』。

## 商業與授權

維持公開 MIT 核心可免費商用。若未來 Open-Core 有獨立加值字典/服務，必須清楚區分授權並獲得合法第三方權利；不能把已有 MIT 社群貢獻偷偷封閉，或把 OSS 贊助資源當成私人商業研發預算。

**結論：不要以工具功能最多作為目標，先把「語境解釋權在使用者、隱私可審計、程式語意保真」做得讓社群可驗證。**
