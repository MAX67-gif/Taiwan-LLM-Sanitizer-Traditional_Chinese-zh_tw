# R9｜臺灣語境產品競爭力與用戶獲取假設

日期：2026-10-24。此文件是原創**產品策略假設／公開競品功能查閱**，不是付費用戶訪談、真實市占率、OpenAI 官方背書或獨家專利評估。

## 競爭對手已經解決什麼

- [DeepL Style Rules](https://support.deepl.com/hc/en-us/articles/21689172557468-Write-your-own-rules)、[Glossary](https://www.deepl.com/en/features/glossary)：支持用詞與風格自訂；不能把「自訂詞庫」當成 TLS 全球獨家功能。
- [Crowdin Glossary](https://support.crowdin.com/glossary/) 與 [In-Context](https://crowdin.com/features/in-context-translations)：具備概念、上下文、討論與實際介面審閱；TLS 不能僅以「提示不同譯法」自稱市場首創。
- [Read Frog Glossary](https://www.readfrog.app/en/docs/glossary)：已支援個人詞彙及逐站控制。TLS 的差異不是單純有備用字典。
- [Immersive Translate](https://immersivetranslate.com/en/docs/)：已有雙語網頁、懸停翻譯及文件閱讀，不應宣稱未有人做到。
- [Chrome Translator API](https://developer.chrome.com/docs/ai/translator-api)：可用本機語言包翻譯，並非所有語言組合、硬體及行動版都可用。
- [OpenCC](https://github.com/BYVoid/OpenCC)：字形及常見詞彙轉換成熟（Apache-2.0），TLS 不能單靠兩岸字形切換建立競爭壁壘。引用不等於可把第三方詞庫整包改授權為 MIT。

## 市場機會：讓翻譯成為「可檢查、可否決、可重用的臺灣語境決策」

**P0：信任先於字數。** 讓使用者理解「這個詞為何被建議？在哪種語境不適用？來源是否有權公開？」產品用「保留原文、正例／反例、差異清單」呈現決策；一般換字器通常不以這些風險作為首頁主訴求。

**P0：使用者擁有語言決策權。** 同個 `menu` 可在 UI 顯示「選單」，在餐飲顯示「菜單」；沒有禁詞，不把 zh-CN 等同錯誤；不支持未經明示的全站批次改寫。

**P1：技術語法與 Prompt 保真。** 對工程師、維護者，沒有毀掉 `JSON key`、`{{placeholders}}`、程式碼及產品專名，比多幾千個不可靠對照更有付費／貢獻價值。Prompt 的角色、工具指令、原文/引用亦需特別保留。

**P1：人人能看懂的臺灣術語解說。** `menu`、`質量`、`終端` 等多義詞卡片顯示「我可以保留原詞」，使用者能留下純本地的領域偏好，製造清楚的口碑傳播點。

**P2：個人擴充與分享。** 只匯出詞條、領域與人選擇的理由，而非全文或瀏覽紀錄；將來才考慮逐站套用、轉換預覽、社群公開分享、詞庫差異報告。

## 三個客群的產品驗證目標（待測，不是已取得的數字）

| 客群 | 首次使用的價值 | 優先衡量的信號 |
| --- | --- | --- |
| 一般讀者 | menu 機器介面／餐飲不混用，原文可回復 | 任務完成率、誤改回復率 |
| 技術創作者／開源維護者 | 專名、JSON 鍵、程式碼、Prompt 保真 | 結構破壞次數、翻譯後修正量 |
| 在地化參與者 | 用詞正反例、來源可追溯、非禁詞政策 | 覆核覆蓋率、爭議可解決率 |

使用者訪談、A/B 實測與有效自然度評測尚未完成，沒有已驗證的留存率、準確率或商業成長數字。若日後量測，須明確自願，嚴守本地隱私。

## 大量蒐詞而不造成詞獄的設計

收集廣泛類別（UI、餐飲、影音、工程、醫療、法律、教育、金融、交通、遊戲、地方口語、歷史詞等）；每筆提案標註 `source_locale`、`target_locale`、`domain`、義項、正反例、詞性、風險、來源與授權、採用狀態、人工審核。**未審查的詞與同義異詞保留為候選，不可因數量多直接推進 runtime。** 遵守可依法引用與授權的原始資料；不能把有 NC、ND 限制的第三方原文與例句不經審查納入 MIT 公庫。

## 預計推進的驗收順序

1. R9：離線自行選詞、正反例卡、用詞備份、手動預覽、權限與結構測試。
2. R10：原創來源表單、可追溯詞義和審稿紀錄；與私人資料隔離。
3. R11：逐網站可撤回的個人詞彙，只能在明確同意後套用；必須先建立衝突、DOM 還原與密碼欄排除回歸。
4. R12：Chrome 真實模型本機評分＋人工雙人審稿，優先分析歧義、專名與自然度；不為了好看的數字污染 R6 凍結題。
5. R13：開放文件的安全差異檢查，擴大 Markdown/JSON/Prompt 品質，依授權與資源再決定 PDF/OCR。
