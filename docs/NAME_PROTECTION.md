# R5 專有名稱保護與翻譯 QA

## 受保護範例

**Codex for Open Source** 是計畫專名，不是可按字面翻成「開源法典」的一般短語。需要中文說明時可使用「OpenAI 的 Codex 開源專案支持計畫」，但這只是中文解釋，**不能冒充 OpenAI 官網的正式中文計畫名稱**。

`lexicon/protected_names_r5.json` 收錄了有來源語境、不可隨意拆開的專名，如 OpenAI Codex、Claude Code、GitHub、ChatGPT、Hugging Face；也提供部分已知錯譯，用於驗證輸出。該詞庫只保護**精確匹配**的片語，不將所有相似詞都全域禁止使用。例如英文小寫 codex 在歷史文獻裡可能真的指古代手抄本。

## 翻譯執行流程

- 來源文字先經特殊片語比對，找出完整專有名稱。
- 翻譯 Provider 在模型呼叫前，以保護 token 暫存名稱、URL、Markdown code/佔位符；輸出後逐一還原並確認 token 數量與順序。**模型若刪除或損壞 token，拒用壞結果並保留安全的原文或詞彙轉換結果。**
- 本地 QA 可將原文與譯文比較，報告專有名稱遺失、已知錯譯與技術符號缺失，但**無法以規則證明整段話語意完全正確**。
- 不可無理由增加「某國用語禁止出現」的規則。當專名是普通詞、品牌或人名有歧義時應保留來源，交使用者選擇。

## 新名稱如何加入？

1. 提供可查證的官方英文產品／專案／計畫名稱及官方 URL。
2. 記錄名稱、可能的 aliases、用途與中文**說明性**翻法（非官方正式譯名需清楚註記）。
3. 加入公開 JSON 後執行 `python tools/generate_names_r5.py`，再跑 `python tools/generate_names_r5.py --check`、`node --test tests/*.js`。
4. 測試「名稱在句子裡」「與技術術語相鄰」「當成常見詞時不應強制改名」「壞掉的模型輸出被拒絕」。
5. 有商標或著作權的第三方資料，只能保存合理的識別名稱與合法的自有說明，不大量搬運來源網站內容。
