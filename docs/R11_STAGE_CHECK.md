# R11 階段檢視與驗收契約

## 目前目標
讓 R9 使用者自選詞彙在已授權網站建立 **人工預覽 → 逐項批准 → 保守套用 → 還原／退出** 的完整路線，避免無語境批次覆寫。

## 已確認限制
- 既有 R5 v0.4.0 原版、R6 frozen V1、R7.1 示範、R8/R9/R10 獨立工作台不覆寫、不偷升級。
- 不得把 R3 883/67 及 R10 40 個人工例句直接當成可執行條目。
- R11 僅是明確 opt-in 的 DOM **文字節點**人工操作，非完整模型翻譯品質保證。
- 網站專屬詞庫只在本機保存，不傳輸到本專案伺服器、不添加網路 API。
- Chrome 擴充功能仍是需解壓的開發者模式版；Tampermonkey 是無額外依賴的單一 userscript。

## 已實作設計（須由對應 CI 再確認發布）
- 與 R9 同一 schema，建立嚴格來源與語境優先路由。
- R11 純核心會話持有頁面節點快照、逐位置批准及 compare-and-restore；不在載入時自動改寫。
- R11 Chrome 分支及 Tampermonkey 單檔獨立發行；原 R5 組件由同一源檔建置，避免複製核心演算法。
- Node/Chromium/Popup/GM 模擬/建置/出版守門整合。

## 下一步
獨立蒐集真實網站可重現問題，保護使用者自行匯入的詞彙資料，評估 R12 真實模型＋自然度雙評審；如 R11 安全 Gate 有任何失敗，維持原主線、不合併。
