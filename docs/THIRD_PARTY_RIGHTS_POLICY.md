# 第三方著作權、商標、隱私與合法資料來源｜公開治理守則

> 此文件為開源專案的保守風險控管原則，不構成正式法律意見。涉及實際爭議、侵權通知或跨境法規時應尋求合格法律專業人士協助。

## 核心界線

- **網路公開可讀不等於公開授權**。只可以使用本人有權使用與重新散布的程式、文章、字典、翻譯、截圖或素材。第三方來源若未明確授權，預設不能進入 GitHub、Git Releases、CI Artifacts 或商業資料庫。
- **觀念與具體表達要區分**。可以學習公開的功能理念、標準、API 文件或事實並以自己原創表達重新實作；不可把他人的完整創作、專有文本、UI 文案或程式碼原樣搬進 MIT Repo。
- **翻譯可能涉及改作**。不能依靠「非營利」「粉絲製作」「已註明來源」「不代表官方」推定取得改作權或再散布權。短語是否具保護性、合理使用是否成立，應按作品及具體情況判斷，不能一概而論。
- **商標與混淆**。第三方品牌的名稱與圖示不應被用來暗示合作、授權、官方背書或主打特定遊戲相容性。必要的事實性識別應最小化並清楚標記來源。
- **保護個資**。不得自行收集登入資訊、玩家姓名、聊天訊息、客戶原文、付款資料或裝置識別碼；測試資料先去識別化、權限最小化。私有 Repo 不代表可任意保存敏感資料。
- **AI 生成也需要來源審查**。使用 AI 或公開網站資料生成的譯文、示範及詞庫，不自動取得第三方原著作權利，也不保證 AI 作品自身的權利歸屬。Contributors 需聲明來源、改作基礎及可授權範圍。

## 產品與發布硬性 Gate

1. 新增任何網站特定整合前，檢查權利人、相關文字/圖像/程式碼來源、服務條款、第三方權利鏈與具體授權條件；**不明確即研究隔離，不公開套件、字庫或下載檔**。
2. 如需要測試功能，優先使用自行編寫的中性、虛構資料和可離線執行的合成 DOM；真實私人頁面不得提交公開 Actions 或 Issues。
3. 每個 Release 驗證最小授權、原創性、可還原、沒有外傳與沒有未驗證官方暗示。對第三方爭議，先暫停公開分享並立即檢查 GitHub Repo／Release／Artifact／Tags／歷史及外部快取。
4. 下架目前檔案與 Release **不會自動清除 Git 歷史、被 Fork/Clone 的副本或外部快取**；不得宣稱能追溯抹除過去公開資料或保證零責任。禁止未經使用者另行核准而 force-push 重寫共享歷史。
5. 私人典藏僅放入授權範圍內、目的明確的必要原創研究，標記未確認權利、唯讀、禁止再發布；不加入受限遊戲資產及使用者個資。定期評估保留必要性及侵權通知。
