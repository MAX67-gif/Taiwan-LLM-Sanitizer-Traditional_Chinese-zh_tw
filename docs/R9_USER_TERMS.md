# R9｜臺灣用語自主選擇工作台（本機獨立 Preview）

日期：2026-10-24。**R9 是獨立單檔 HTML**，不替換通用 Chrome/Tampermonkey R5 v0.4.0、不改 R6 凍結品質題庫、不變更 R7.1 網站示範及 R8 既有工作台。

## 第一個可直接使用的差異化產品

直接下載 [R9 的獨立 HTML 工作台](../examples/TW_User_Context_Lab_R9_20261024.html)（或 GitHub Releases 中的 R9 資產）。下載完成後雙擊開啟；輸入文字、選擇領域、按「分析」，逐項決定使用某個臺灣常用說法，或完全保留原文。再按「產生預覽」，即可並排檢視原文與改動、逐項差異。**預覽不修改原文或其他網頁。**

若工作中反覆使用同樣詞彙，可按「記住這個選擇」，或在新增詞條區自己輸入原詞、想採用的詞、適用領域、備註；也能決定「保留原詞」。相同來源詞在 UI、餐飲、金融可保存各自偏好，不採全域盲替換。**領域 auto 只會顯示不同含意的可能選擇，不會以不確定情境保存自動規則。**

## 可攜式設定檔，不用登入

- 手動按「匯出詞彙偏好 JSON」，下載 `tls.personal-glossary.v1` 的本機設定檔。只包含你主動保存的詞彙、領域、偏好與備註；**不包含貼在檢視框的完整原文**。匯出時請留意：自己加入的術語與備註也可能是機密，請勿在公開 Issue 直接貼出私人設定檔。
- 匯入先由人選檔、再按「匯入」；僅取代目前頁面記憶體中的偏好，不更新瀏覽器設定或其他檔案。工作台沒有 localStorage、自動儲存、雲端同步與網頁外連接。
- 目前限制為 **200 條詞、64 KiB JSON、原文 12,000 字元、最多 100 個詞彙位置**；非法欄位、錯誤 schema、重複詞與非文字結構直接拒絕。匯出 JSON 的字元並不代表已完成個資去識別化。

## 資料分層與狀態

| 資料 | 數量 | 用途與限制 |
| --- | ---: | --- |
| R3 編輯種子 | 67 | 原有保守詞彙；R9 不擅自提升其權限 |
| R3 待審候選 | 883 | 顯示詞彙建議，不代表翻譯品質或自動替換授權 |
| R9 原創正反情境例 | 28 | `lexicon/context_examples_r9.json`，**僅編輯草稿**、不能作詞庫正式認證 |
| R9 使用者偏好 | 0 起，最多 200 | 僅使用者在單頁中加入，可下載 JSON，不能直接當作公版建議 |

R9 對話檢視器沿用 R8 的程式碼區塊、URL、部分 HTML 標籤、JSON 鍵、占位符與語法排除能力。**仍不是完整 HTML/Markdown/JSON parser**；遇到解析不了的語境、引文、專名、醫學或法律內容，一律需要人工判斷。保留原文是正常且被尊重的選項，絕無任何詞彙黑名單。

## 驗收與再現

1. `node tools/build_user_terms_r9.js --check` 驗證單檔 HTML、原 R3 詞庫與原創情境例的組裝完全一致。
2. `node --test tests/test_user_terms_r9.js tests/test_context_examples_r9.js` 檢查匯入格式、語法防護、預覽必須明示選詞、詞彙歧義。
3. `python tests/test_user_terms_browser_r9.py` 在 Chromium 確認從選字、預覽、JSON 下載、重新開頁不儲存，到匯入恢復的真實使用流程。
4. CI 的 publication_guard.py 仍禁止私人資料路徑與未知文件，新公開文件僅逐一加入 allowlist；沒有放寬秘密掃描或執行期對外送資料 API 的限制。

## 下一階段門檻

**不應立即將個人偏好注入 R5 Chrome/Tampermonkey 全站 runtime。** 先做逐站匯入授權、衝突預覽、復原驗證、與不可信網頁隔離，再考慮通用套用。社群候選每筆應補來源權利、正例、反例、兩名人工審稿的決策紀錄，再評估是否「建議」或「可選擇性套用」。未經真實翻譯品質評測，不能宣稱 950 個詞等於 950 個正確翻譯。
