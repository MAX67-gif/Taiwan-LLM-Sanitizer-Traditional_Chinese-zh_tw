# R206｜Suite 17.5.0 發布前唯讀雙重身分檢查（2026-11-24）

**狀態：A 路線 Draft 工程防護。禁止直接合併主線、不得以此作為發布授權；新版 17.5.0 尚未發布。**

## 為何新增

R199 已從 GitHub Suite 17.4.0 真實下載全部 29 件來源資產並逐一驗證 SHA256。R202 已能利用這些原始位元組組成 30 工具／30 附件的獨立候選，且獨立檢查器會比較原 29 項與新套件中對應的位元組。**然而已驗證套件內容不表示 GitHub 新 Tag 尚未佔用，也不能保證當前帳號有權發布。**

R206 補上真正的「準備建立新版 Tag 前」唯讀守門，不為了顯示 PASS 而編造任何發行結果。

## 具體流程與安全邊界

1. 由 R199 在本輪 PR 使用 GitHub Actions 憑證只讀下載官方 17.4.0 全部 29 個附件，核對標籤、來源、大小及 SHA256。
2. 由 R202 真正產生 30 件 source-backed 候選，並透過獨立檢查器再次核對官方來源原始位元組、候選 Manifest、註冊表與內部 ZIP checksum。
3. R206 執行 `tools/check_suite_175_release_preflight_r206.py`，先重做上述來源完整性檢查，再依序向 GitHub **只讀 GET**：
   - `releases/tags/all-tools-suite-v17.5.0`；
   - `git/ref/tags/all-tools-suite-v17.5.0`。
4. 兩者都必須回應已驗證的 GitHub 404 `Not Found`，才可產出**非發布的「標籤目前尚未存在」紀錄**。存在 Release、標籤移動、GitHub 403、429、5xx、回應異常或網路失敗都會 Fail Closed。
5. R206 完成後輸出固定 `TLS_R206_VERSIONED_RELEASE_PREFLIGHT_NOT_READY.json`。內容包括正式來源與候選 SHA、30 件資產數、唯讀查詢次數、仍未完成的部署與真人驗證欄位，但沒有原稿或個資。輸出不得寫入原始碼目錄，已有檔案不得覆寫。

## 不能誤用的地方

- **唯讀雙 404 不是新 Tag 的原子保留**：別的操作者可能在檢查後建立 Tag；將來真正正式發布的當下必須再次檢查，並由單一發布者／併發鎖控管。
- R202 工程候選的輸出檔名仍包含 `NOT_RELEASED`，**不能直接改名當正式 Suite 17.5.0**。
- 目前仍缺真正可發布的 17.5.0 版本化 Builder、Validator、Publisher、六語文件同步及全套 Draft／Published 階段新鮮下載回驗。R206 沒有完成這些工作，也不授權發布。
- 不使用 17.4.0 舊版 Publisher 替 17.5.0 上傳，更不能覆寫舊正式 Release。
- 新增 `tests/test_suite_175_release_preflight_r206.py` 正向與反例：兩個 GET 必須不同；任一 Tag/Release 存在、403、偽造 404、網路錯誤、錯誤來源數量、假發布權限都會拒絕。

## 本輪學習與未來升級

**成功路徑：** 先確認真實來源位元組 → 已驗證完整 30 資產候選 → 獨立向 GitHub 檢查兩種標籤存在形式 → 留下只讀證據並維持發行封鎖。

**踩雷：** 「GitHub 搜尋不到」不是可靠的 Tag 不存在證據；403 權限不足與 429 限流不可以當 404；即使兩個 URL 都是真正 404，也只是檢查當下的狀態，不能跳過發布時再次檢查。

**可重用規則：** 研究 Preview 的 PASS、官方原始資料 SHA 驗證、發布授權、正式發布與真人語言品質證據必須分開統計，不得互相替代。

**下一優先動作：** 依此 fail-closed 前置契約建立新版 17.5.0 完整 Publisher 與全附件 Draft／Published 雙重獨立回驗，在真實權限、原始資產與六語說明完成之前，保持 PR #60 為 Draft。
