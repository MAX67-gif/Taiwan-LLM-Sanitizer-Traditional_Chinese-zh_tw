# R196｜反證優先・保護優先・未知保留路由研究（2026-11-13）

> **狀態：純研究 Shadow。不可自動改寫，不接入 R19 UI，不變更 R17.2 approved 詞庫，不授權發行。**

## 問題

R194 已有 52 組原創正例／反例／程式保留例，但如果同一個詞同時在不同語境出現，只有「命中正例」不足以決定全域替換；例如 `menu` 可能指軟體選單，也可能是餐廳菜單；`token` 可能是 API 權杖，也可能是語言模型詞元。

## 本輪實作

`research/comparison/r173/context_conflict_router_r196.js`

- 對同一個已存在的 R194 原創資料 `CTX###`，只執行**逐字精確匹配**，每批最多 12 個觀測。
- 五態：`PROTECTED_KEEP`、`CONFLICT_KEEP`、`COUNTEREXAMPLE_BLOCK`、`UNKNOWN_KEEP`、`PREFERRED_SUGGESTION`。
- 以 **保護 > 相反語境衝突 > 反例阻擋 > 未知保留 > 正例建議** 為優先序；即使有正例，也不會因大量重複或混合未知句而自動批准。
- 對未知或資料庫以外的句子一律保留；不推論語意、不輸出原始文字、不發出網路請求、不寫入磁碟。
- 每次返回 `auto_apply:false`、`promotion_permission:NONE`、`human_quality_verified:false`。
- 所有語境案例仍為原創合成測試，未經人工母語語言品質評估，不能宣稱真實世界準確率。

## 實際五態例子

| 輸入觀測 | 研究路由 | 為何 |
|---|---|---|
| 原創軟體 `menu` 正例 | PREFERRED_SUGGESTION | 有建議，不允許自動改 |
| 餐廳 `menu` 反例 | COUNTEREXAMPLE_BLOCK | 不可硬替換成「選單」 |
| 原創軟體正例 + 餐廳反例 | CONFLICT_KEEP | 同詞不同領域，兩邊都保留供人判斷 |
| 正例 + 未知新句 | UNKNOWN_KEEP | 反證不足，不能推論新句 |
| 原創程式碼片段 + 其他正例 | PROTECTED_KEEP | 受保護程式碼優先於語言替換 |

## 驗收／不可誤用規則

1. 共 52 組詞，為每組測 10 種單例、衝突與保護組合，並加入未知句、同詞重複、混雜詞、偽造核准欄位、無效 Unicode 和長字串負面案例。
2. 結構 PASS 與資料集上分流 PASS **不是**真人語境判斷、語義等價或未曝光資料上的推論能力。
3. 不能把本路由套用到使用者整篇文件；研究器的 `EXACT_ORIGINAL_SYNTHETIC_FIXTURES_ONLY` 是強制範圍。
4. 保留 `R194` 原始 52 組及既有 17.4.0 Release；沒有新的官方工具或新版本發布。
5. 要升級成正式功能，需新增獨立有授權的未曝光 OOS 正反例、真人判讀、使用者明確選擇、語法保護、錯誤恢復，並完成新版 Suite 發行程序。

## 經驗規則

**成功路徑：** 正反例及受保護情境先驗證；衝突直接保留；每個決定都提供不含原稿的原因與數量。**踩雷：** 同字串不代表同語義，程式 `token` 不等於 API 權杖；把多個孤立正例誤算成功率、擴張成自動替換會引入無法追蹤的資料污染。

**下一步：** 在新版本的非自動審查 UI 中展示「對照例與反證」，但先用 OOS 真實權利清楚資料做人工驗證，再考慮 Runtime。
