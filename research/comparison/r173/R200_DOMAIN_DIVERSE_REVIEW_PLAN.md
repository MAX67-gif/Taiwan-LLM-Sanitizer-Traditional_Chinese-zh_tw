# R200｜跨領域分散審查排程（R194／R196／R197 唯讀研究）

**定位：資料量沒有增加。原本 52 組原創合成案例、260 筆派生審查工作項目完全保留。**

## 使用者問題與新解法

R197 已經將受保護／語境衝突／反例／未知／僅建議，分成 5 × 52 筆待人工審查工作項目。
但原始佇列以案例 ID 排列，若僅從前面依序檢查，可能集中在 software_ui 類別，讓不同領域的反例被延後。

R200 新增 `context_review_plan_r200.js`，在每一風險分級中，以固定的領域 round-robin 排列原始 52 案；
優先順序依序為 P0 結構、P0 衝突、P1 反例、P1 未知、P2 僅建議。
再按預設 20 筆一批切分成 13 個**待辦批次**。這只改善人工審核的安排，不增加樣本與判斷準確率。

## 可重現驗證與資料安全

- `node research/comparison/r173/context_review_plan_r200.js --check`
- `node --test tests/test_review_plan_r200.js`
- 共 260 項、每狀態 52 項、無遺漏／新增 ID；分散 P0 起始領域；確定性輸出；
  篡改審核狀態、強制自動替換或附加原文會被拒絕
- 輸出僅保留：R194 案例 ID、研究 domain ID、R197 審查項目 ID、風險優先級與批次；
  不提供任何合成或真實原文、URL、Prompt、檔案內容
- `human_reviews_completed=0`，`release_permission=NONE`，
  `human_quality_verified=false`，`automatic_rewrite_enabled=false`

## 成功路徑、限制與下一階段

1. 成功路徑：不改 R194／R196／R197；從既有唯讀佇列生成新的分散排程；只在 Node 測試及 GitHub CI 成功後合併研究程式。
2. 限制：跨領域順序不是語義模型、不是公平性或準確度量測；所有樣本都已曝光，不可冒充 Fresh-OOS。
3. 踩雷：`52 × 5 = 260` 是派生排程項目，不是 260 個新增真人案例；domain diversity 只是避免審閱順序過度集中，不是模型能認出未知語境。
4. 下一步：另行收集具合法權利與同意的審核結果，按域追蹤人審證據，再考慮是否將經核准的候選用語放進產品；此程式**沒有**升級權限。
